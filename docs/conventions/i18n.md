# i18n conventions

Decision and locale list: ADR-0004. This file is the day-to-day checklist.

## Rules

1. No user-facing string literals in UI code, notifications or emails. Use translation keys.
2. Every new key is added to **all four** catalogs (`en`, `me`, `ru`, `tr`) in the same PR. `en` is
   the source; the key-parity test must pass.
3. Keys are namespaced and semantic: `booking.confirm.title`, `business.services.empty`,
   `errors.SLOT_TAKEN`. Never use the English text as the key.
4. Use ICU plurals/selects instead of string concatenation:
   `"{count, plural, one {# booking} few {# bookings} other {# bookings}}"` — note that `me` and `ru`
   need `one/few/other` (and `many` for `ru`).
5. Format dates, times, numbers and currency with `Intl` using the locale's BCP-47 tag (`me` →
   `sr-Latn-ME`) and the **business timezone** for booking times.
6. API error `code`s map to `errors.<CODE>` keys on the clients.
7. Crnogorski/Srpski strings are written in **Latin** script.
8. When unsure about a translation, still add it and list the keys in the PR under "Translations to
   verify".

## Where catalogs live

`packages/i18n/messages/<locale>/<namespace>.json` (exact layout is fixed by the i18n package task;
update this line when it lands).
