# #11 — Add i18n package with locale resolution and catalogs (@najme/i18n)

- Issue: https://github.com/Dmitry-Bulavko/najme/issues/11
- Status: Implemented
- Related: ADR-0004, `docs/conventions/i18n.md`

## Goal

A single runtime-agnostic package (`@najme/i18n`) that defines the four supported locales, resolves
a user's locale from a list of language preferences (device/browser/`Accept-Language`), and ships
the `common` ICU message catalog for `en`, `me`, `ru`, `tr`. Consumed later by `apps/api`,
`apps/web` and `apps/mobile`.

## Approach

Mirror the `@najme/contracts` package layout (tsup dual ESM/CJS build + `.d.ts`/`.d.cts`, the same
`exports` map, `@najme/config` tsconfig/eslint/vitest presets). Catalogs are plain nested JSON
objects imported statically from `src/index.ts`; `resolveJsonModule` (already on in
`@najme/config/tsconfig/base.json`) lets TypeScript type-check them, and `tsup`/esbuild inlines
their content into the built `dist/index.js` / `dist/index.cjs`, so no separate JSON files need to
ship in `dist` and every bundler (Next.js, Expo/Metro, Node) gets the same values.

Locale resolution only looks at the **primary language subtag** (the part before the first `-`/`_`),
so script/region subtags (`sr-Cyrl-RS`, `sr_ME`) do not need special-casing beyond the ADR-0004
mapping table.

## Implementation notes

- JSON-import approach: catalogs are `.json` files under `src/catalogs/<locale>/common.json`,
  imported with `import common from './catalogs/en/common.json' with { type: 'json' }`. The
  `module: "NodeNext"` preset in `@najme/config/tsconfig/base.json` requires the `with { type:
"json" }` import attribute for JSON imports (plain `resolveJsonModule` imports are rejected under
  `NodeNext`); esbuild/tsup and Vitest both understand the attribute and strip it during bundling.
  `tsup` inlines the JSON content into `dist/index.js`/`dist/index.cjs` at build time — verified by
  inspecting `dist/index.js` after `pnpm --filter @najme/i18n build`.
- `resolveLocale` matches on the primary language subtag only (lowercased, `_` normalized to `-`),
  per ADR-0004's mapping table; first matching candidate wins, invalid/unknown candidates are
  skipped, empty input falls back to `en`.
- Added an explicit `eslint`/`typescript`/`vitest`/`tsup` devDependency set (matching
  `@najme/config`'s versions) so `pnpm --filter @najme/i18n lint|typecheck|test|build` never falls
  back to a globally installed binary — this was the CI failure mode found on `@najme/contracts`.
